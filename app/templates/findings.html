Findings

A running technical log of things discovered while building this product — API limitations, cost/compliance notes, verified behavior. English only, and separate from the Guide, which covers how to operate the UI.

2026-09-09 Google API

Gemini's Google Search grounding has no country/language parameter

Confirmed directly against the official docs: the Gemini API's GoogleSearch grounding tool has no parameter to control the language, country, or geographic origin of the search. The docs state grounding "works with all available languages," but nothing biases which region's results come back.

Current workaround: a system_instruction text hint built from the prompt's market (language + label), editable per provider on Settings. This nudges the model's answer language and framing — it does not change what the underlying search actually retrieves.

For comparison: Anthropic's Claude web_search tool has a real user_location parameter (city/region/country/timezone) — actual geo-targeting, not just a text hint.

Source: ai.google.dev/gemini-api/docs/google-search

2026-09-09 Update

user_location is now live (the Anthropic adapter, app/adapters/anthropic.py) — but it does not accept every ISO 3166-1 country code. A real run against market cs-CZ was rejected outright: 400 invalid_request_error: "Country code CZ is not supported." The exact supported list isn't published anywhere we found — treat it as trial-and-error per market, and expect a run to legitimately fail with status error for some markets, not just on transient API problems.

The system_instruction template (Settings) is now split per provider: Gemini keeps the full location-simulating + language template (it has no real alternative), Anthropic's was trimmed to language-only ("Answer in {market_language}.") — repeating the location-simulation sentence there would just duplicate what user_location already does for real.

2026-09-09 Competitive / Methodology

How a dedicated AI-visibility competitor (Peec AI) handles market targeting

Per Peec AI's own comparison page: "Peec AI uses UI scraping, not API polling, with dedicated infrastructure in every country it supports, ensuring the results it collects exactly mirror what actual users see in their region." They explicitly frame this against competitors that "artificially inject geographic identifiers" into prompts — i.e. text hints like our Gemini fallback above.

Concretely: real regional infrastructure (servers/IPs physically in each of 80+ countries) scraping the consumer-facing chat UIs (chatgpt.com, gemini.google.com, ...) rather than calling official APIs with a location parameter. Whatever IP-based geolocation the consumer product itself already does happens naturally — no per-provider API quirk to work around (e.g. the CZ rejection above wouldn't be a Peec AI problem in the same way).

Not something to build now — a global proxy/infrastructure network plus UI-scraping (with its own fragility and ToS exposure against the AI vendors' consumer products) is a different order of operational complexity than this project's current vertical-slice scope. Recorded here as context for later: if per-provider API location parameters keep hitting hard limits (unsupported countries, no parameter at all), this is the architecture a real competitor uses instead.

Source: peec.ai/comparison/peec-vs-profound, docs.peec.ai/setting-up-your-prompts

2026-09-09 Cost & Compliance

Free-tier Gemini API usage is used to improve Google's products

Per Google's own terms: on the free/unpaid tier, "Google uses the content you submit to the Services and any generated responses to provide, improve, and develop Google products and services," and "human reviewers may read, annotate, and process your API input and output."

On the paid tier, this is explicitly excluded: "Google doesn't use your prompts... or responses to improve our products" — paid-tier data is used only for abuse detection and required legal disclosures.

Regional exception that applies to us directly: users in the EEA, UK, or Switzerland get the paid-tier data protections even on the free tier. The Czech Republic is in the EEA, so this likely already covers our current testing — but real client-sensitive prompts should still move to the paid tier before any production use, since the free-tier terms remain the default everywhere else.

Source: ai.google.dev/gemini-api/terms

2026-09-09 Request Parameters

What we send to Gemini today, and what else is available

Currently sent for every run (app/adapters/google.py): model, contents (the prompt text, verbatim), tools=[GoogleSearch()] (grounding), system_instruction (the market-derived hint above). That's the minimum needed for a grounded, market-framed answer — nothing more, nothing configurable per run yet beyond model and market.

Available on GenerateContentConfig but not used yet:

  • Generation control — temperature, topP/topK, maxOutputTokens, stopSequences, seed (reproducibility)
  • Structured output — responseMimeType + responseSchema (forces JSON matching a schema — directly relevant once the analysis-skills phase needs structured results)
  • Safety — safetySettings (per-category content filtering thresholds)
  • Other — candidateCount, cachedContent, additional tools (function calling, code execution)

Source: ai.google.dev/api/generate-content

2026-09-09 Request Parameters

What we send to Claude today, and what else is available

Currently sent for every run (app/adapters/anthropic.py): model, max_tokens (hardcoded 4096 — sized for a complete grounded answer, not the model's full 128K capacity), messages (the prompt text, verbatim), tools=[web_search_20250305] (max_uses: 5, user_location from the run's market), system (the language-only hint from Settings, when set).

Available on the Messages API but not used yet:

  • Effort/thinking control — effort (Claude 4.6+ models default to "high"), thinking (adaptive/extended reasoning). Not relevant for a single grounded Q&A today — worth revisiting once the analysis-skills phase needs more deliberate reasoning.
  • Prompt caching (cache_control) — cache reads cost 10% of base input price. We re-send the same prompt text across markets with only system differing; caching the prompt itself could cut cost noticeably at higher run volume.
  • Newer web_search tool versions — web_search_20260209 (dynamic filtering, code-execution-backed) and web_search_20260318 (response-inclusion control) exist; we deliberately use the oldest for a simpler, more predictable response shape.
  • Batch API — 50% discount on both input/output tokens, for non-time-sensitive bulk runs (relevant if a future scheduled/batch analysis phase runs many prompts at once).

Citation shape differs from Gemini — Anthropic attaches citations inline per text block (block.citations), not one grounding-metadata blob. app/adapters/anthropic.py walks all text blocks in order and assigns a running position — worth knowing before any future analysis-skill code assumes Gemini's shape.

Known gap: pause_turn — a very long-running search can return stop_reason: "pause_turn" instead of finishing; this adapter doesn't resend/continue that. Hasn't happened in testing yet, but raw_payload.stop_reason always shows if it does.

Real per-run cost isn't fully captured in /ai-models pricing — web search itself costs $10 per 1,000 searches, on top of token costs. Our cost_per_1k_input_usd/output_usd fields only capture token price — a run's true cost is token cost + this flat search fee, currently invisible in the UI.

Source: platform.claude.com/docs/.../pricing

2026-09-09 Cost & Compliance

Anthropic API data isn't used for model training (commercial terms)

Unlike Gemini's free tier (see above), Anthropic's API — commercial terms, which cover our usage — does not train on input/output data at all, on any tier: inputs/outputs are auto-deleted after 7 days by default, and retained data is "never used for model training without your express permission." The August 2025 opt-out-based training-data policy change that applies to Claude.ai consumer accounts explicitly does not apply to API access.

Options if this project ever needs different retention: 30-day retention via a Data Processing Addendum, or a Zero Data Retention agreement (qualifying enterprise accounts) where nothing is stored beyond abuse-screening needs.

Source: Anthropic Privacy Center, API and data retention docs
